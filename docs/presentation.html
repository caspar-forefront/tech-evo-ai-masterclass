What is a coding harness?
The harness is the program around the model.
It sends the conversation to the model, runs the tools that the model asks for, and sends the results back.
In practice: a system prompt, tools, and a loop
In the next 30 minutes, you look inside a harness of 98 lines. After that, you extend it.
Learning from first principles removes the magic that these tools seem to have.

Composition

A harness is three parts around a model

+
The model
The part that you do not control. It is trained to work as a coding agent. The harness reaches it with one stateless HTTP call to a provider. The next slide shows that call.
1
The system prompt
Tells the model where it is, what it can do, and how to ask for it.
2
The tools
Capabilities that the harness offers. The model chooses a tool, and the harness runs it.
3
The loop
Send the conversation, run the tool that the model asks for, send the result back. Repeat until a reply has no tool call.
Agent = Model + Harness. The model supplies the intelligence. The harness supplies the environment.
The protocol · the provider, part 1

A conversation with a model is one stateless HTTP call

Request · POST /v1/chat/completions
{ "model": "deepseek/deepseek-v4-flash", "messages": [ { "role": "system", "content": "You are a helpful assistant." }, { "role": "user", "content": "Hello" } ] }
Response
{ "choices": [ { "message": { "role": "assistant", "content": "Hi! How can I help?" } } ] }
The API keeps no state. The harness sends the full conversation on each request.
The protocol · the provider, part 2

The whole provider is one function sendMessages()

async function sendMessages(conversation: Message[]) { const response = await fetch("https://openrouter.ai/api/v1/chat/completions", { method: "POST", headers: { "Authorization": `Bearer ${process.env["OPENROUTER_API_KEY"]!}`, "Content-Type": "application/json", }, body: JSON.stringify({ model: "deepseek/deepseek-v4-flash", max_tokens: 4000, messages: conversation, }), }); const data = await response.json() return data.choices[0].message.content; }
This is the request from the previous slide in a function: one fetch, one bearer token, one JSON body.

Anatomy of a system prompt

This harness: the whole prompt, about 130 words

tool docs

Building block 2 · The tools

The tools the least that a coding harness needs, with their implementations

const tools: Record<string, (input: any) => Promise<string>> = {
read
read the contents of a file
read: ({ path }) => readFile(path, "utf8"),
write
create or overwrite a file
write: async ({ path, content }) => { await mkdir(dirname(path), { recursive: true }); await writeFile(path, content, "utf8"); return `write: wrote ${content.length} bytes to ${path}`; },
edit
replace exact text in a file
edit: async ({ path, oldText, newText }) => { const content = await readFile(path, "utf8"); await writeFile(path, content.replace(oldText, newText), "utf8"); return `edit: updated ${path}`; },
bash
run a shell command
bash: ({ command }) => new Promise((resolve) => { exec(command, (_error, stdout, stderr) => { resolve(`${stdout}${stderr}`.trim() || "(no output)"); }); }),
A tool is a function from arguments to text. With bash, the agent can change every file that your user account can change.
Building block 2 · The tools

A tool call is one line of text

1The system prompt describes the format
When you want to use a tool, reply with exactly one line in the format: tool: NAME({"arg": "value"})
2The model writes that line
assistanttool: bash({"command": "find . -name '*.ts' | wc -l"})
4The result goes back as a user message
usertool_result("1425")
3The harness finds the line and runs the tool
function extractToolCall(text: string): (() => Promise<string>) | null { for (const line of text.split("\n")) { const match = line.trim().match(/^tool:\s*(\w+)\((.*)\)$/); if (!match) continue; const tool = tools[match[1]!]!; const input = JSON.parse(match[2]!); return async () => `tool_result(${JSON.stringify(await tool(input))})`; } return null; }
The model only writes text. The harness runs the tools. This format is our own. Most APIs have a native one: breakout topic 1.
Building block 3 · The loop

The loop

const conversation: Message[] = [{ role: "system", content: systemPrompt }]; async function runLoop(prompt: string): Promise<void> { conversation.push({ role: "user", content: prompt }); while (true) { const reply = await sendMessages(conversation); conversation.push({ role: "assistant", content: reply }); console.log(reply) const toolCall = extractToolCall(reply); if (toolCall === null) break; const output = await toolCall(); conversation.push({ role: "user", content: output }); } }
The loop stops when a reply has no tool call. The model decides when it is done.
Building block 3 · The loop

The loop, step by step a real session, verbatim

const conversation = [{ role: "system", … }]; async function runLoop(prompt: string): Promise<void> { conversation.push({ role: "user", content: prompt }); while (true) { const reply = await sendMessages(conversation); conversation.push({ role: "assistant", content: reply }); console.log(reply) const toolCall = extractToolCall(reply); if (toolCall === null) break; const output = await toolCall(); conversation.push({ role: "user", content: output }); }}
Seven messages, two tool calls, and one correction that the model made on its own. Nothing is edited. Only the system prompt is cut to fit.
The last reply has no tool: line. extractToolCall() returns null, and the loop stops. The model decided that it was done.

user
system prompt + tool docs
request 4
Long sessions are slower and cost moreEach request sends everything before it again. Prompt caching makes the repeat cheaper, not free.
The agent forgets after compactionWhen the window is full, the harness replaces the history with a summary. Details that the summary drops are gone.
A new session helpsA new conversation holds only what this task needs. Less noise, fewer tokens, better answers.
The conversation is the memory of the agent. It grows with each request, until compaction replaces it with a summary.

Help users inspect files, run commands, and modify code. <tools> - read: Read a file's contents. Arguments: { "path": string }. - write: Create or overwrite a file. Arguments: { "path": string, "content": string }. - edit: Replace exact text in a file. oldText must appear exactly once. Arguments: { "path": string, "oldText": string, "newText": string }. - bash: Run a shell command. Arguments: { "command": string, "timeout"?: number (ms) }. When you want to use a tool, reply with exactly one line in the format: tool: NAME({"arg": "value"}) Use compact single-line JSON with double quotes. If no tool is needed, just respond normally with your answer. </tools> <cwd> ${process.cwd().replace(/\\/g, "/")} </cwd> `; const conversation: Message[] = [{ role: "system", content: systemPrompt }]; async function runLoop(prompt: string): Promise<void> { conversation.push({ role: "user", content: prompt }); while (true) { const reply = await sendMessages(conversation); conversation.push({ role: "assistant", content: reply }); console.log(reply) const toolCall = extractToolCall(reply); if (toolCall === null) break; const output = await toolCall(); conversation.push({ role: "user", content: output }); } } process.stdin.setEncoding("utf8"); process.stdout.write("> "); for await (const chunk of process.stdin as AsyncIterable<string>) { const prompt = chunk.trim(); if (prompt) await runLoop(prompt); process.stdout.write("> "); } console.error(JSON.stringify(conversation));

Breakout session · explore with an agent

Make the agent read, then check its sources

An agent answers from one of two places: the sources that it reads now, or the memory of the model. The memory is often out of date for tools that change each month.
1
Make the agent read
Give it the source: a file, a repository, or the URL of the docs.
2
See where each answer comes from
Open the files and the pages that the agent names.
3
Check what matters
Test a claim yourself before you rely on it.
